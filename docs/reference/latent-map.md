# The 🌌 latent map

`semantic_anarchy/latent_map.py` (torch-free) projects every image's `.npz` onto the corpus PCA (`project`/`unproject` are exact inverses inside the span), builds an *explored* frame by PCA over a fixed JL sketch of the gallery, and scores `off_manifold` (share of the deviation outside the corpus span). `scripts/latent_map.py` adds lineage edges (`parent`/`parent_b`, walks chained by `walk_frame`) and labels axes with the corpus prompts at each extreme (it replays `fit`'s seeded `corpus_embeddings` draw, so labels need the same prompt file). `GET /api/latent-map` reruns it whenever the `.npz` set changes — outside the GPU queue. Frontend: `features/latentmap/` (vanilla three.js, lazy-loaded): `scene.ts` owns the canvas (glow-sprite nodes, marching-cubes hull over the robust core, asinh display squash, labelled axes), `LatentMap.tsx` maps data → typed arrays and reuses the gallery `Lightbox`; ⇧-click appends to the 🎬 timeline.

The dashboard builds against the sidebar's selected distribution and, for a prompt corpus, that corpus's own `.txt`; the cache signature includes both, so switching rebuilds. Nodes are found by stem via `io_utils.find_image`, so PNG and JPG renders both count. Axis and corpus-point labels only appear when the prompt count equals the fit's `n_samples`; a fit made from picked images has no prompts, so its axes are just `PC1`, `PC2`, ….
